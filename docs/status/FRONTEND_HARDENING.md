# Frontend Hardening Brief

Goal: every page works against the **real API on a real database**, in both languages, for every role, with no broken endpoints, no console errors and no placeholder text. Fixture mode stays, but it must be proven identical in shape to the real API.

Read this whole file before starting. Commit after each section with a one-line status.

---

## 1. Local full stack without Docker

The frontend has so far only run against `VITE_FIXTURES=1`. That proves the pages render, not that they work.

- Add `scripts/dev_stack.py`: one command that starts pgserver (available now that PostGIS is optional, per N4), applies all migrations, loads seeds, loads the fixture dataset **into the database through the real loaders** (mock Form 20 → parser → validation → promote, not direct inserts), refreshes the views, creates one user per role, and starts uvicorn on port 8000. It prints the users and passwords and the URL.
- It must work on Windows PowerShell with no admin rights and no Docker.
- `web/vite.config.ts` proxies `/api` to `http://localhost:8000` when `VITE_FIXTURES` is not set.
- Document it in `RUN.md` as the default way to run locally.

## 2. Endpoint inventory and contract

- Produce `docs/ENDPOINTS.md`: a table of every API route (method, path, roles, query params, response model) and every frontend call site (file, component, the route it calls). Flag any frontend call to a route that doesn't exist, any route with no frontend caller, and any mismatch in params or response fields.
- Every API route has an explicit pydantic response model. No bare `dict` responses.
- Generate frontend TypeScript types from the API's OpenAPI schema (`openapi-typescript`), and make every fetch use them. Remove hand-written response types.
- Fixtures are validated against the same response models in a test, so fixture mode can't drift from the real API. If the fixture layer can instead be generated by running the real API on the fixture database and saving responses, prefer that.
- Add a test that calls every route, for every role, against the seeded dev database, and asserts: correct status for the role (200 or 403, never 500), and the response validates against its model.

5. CLI commands in data-health cards wrap, or truncate with a copy button. No horizontal scrollbars inside cards.
6. Proper i18next plurals for "dataset(s)", "item(s)" and similar, in both languages.
7. Header shows the platform name, not "Giridih Monitor". The constituency is shown by the switcher only.
8. Group the 17 navigation items into 5–6 menus (e.g. Results, Voters & community, Politics & news, Analysis, Admin). Keyboard accessible.
9. The "A" button gets an accessible label and a tooltip, or is removed.

Booth map:
10. **Base map tiles.** Cause already confirmed, no investigation needed: the tile URL (`https://{s}.basemaps.cartocdn.com/light_all/{z}/{x}/{y}{r}.png`) is unchanged since baseline `1b0efed`; CARTO's keyless endpoint now returns "API key required" watermark tiles (verified directly in a browser). Record this in `DECISIONS.md`, then:
    - Remove the CARTO URL from the code entirely.

## 4. End-to-end checks on every page

Use Playwright against the dev stack from section 1, not fixtures. For **every route × both languages × every role**:

- No console errors or warnings from app code.
- No failed network requests (4xx other than the expected 403s, any 5xx, any failed tile or font load).
- No rendered text containing `{{`, `undefined`, `NaN`, `null`, `[object Object]`, or `Invalid Date`.
- Numbers in Indian digit grouping; percentages with consistent decimal places.
- Loading, error and empty states each render correctly. Test the error state by making the API return 500 for that page's route.
- Switching constituency updates every figure on the page. Test Giridih, one other AC with AC-level data only, and an AC with nothing loaded.
- A hard refresh on a nested route (e.g. `/acs/32/booths?sort=margin`) loads the same view.
- A block-role user can't reach another block's data or the caste pages, including by typing the URL.
- An expired session sends the user to login and returns them to the same page after.
- Layout holds at 1440 px, 1024 px and 390 px wide: no overlapping text, no horizontal page scroll.

Save a screenshot per route × language × width into `tests/e2e/screenshots/` and list them in the report.

## 5. Page-level behaviour

Go page by page and make each one do its job, not just render:

- Booth table: sorting, every filter, column presets, CSV export (check the file opens and matches the view), row click opens the booth card.
- Booth card: every tab loads and shows real data or an honest empty state.
- Map: filters change markers; clicking a marker opens the booth card; ungeocoded booths are listed somewhere visible.
- Caste pages: low-confidence estimates greyed; the scatter shows the caveat.
- Scenario: sliders update the result; winner and sensitivity range shown correctly for every contest pair.
- Compare: all six ACs present, with unverified badges where seeds are unverified.
- Admin: review queue actions work end to end (accept, reject, reassign) and the change shows up on the affected pages after refresh.

## 6. Quality basics

- Lazy-load routes; report the main bundle size before and after.
- Self-host fonts (A11), with a Devanagari font that renders every glyph used.
- Every interactive element reachable by keyboard, with visible focus and an accessible name.
- Colour choices readable for colour-blind users (the map's saffron vs green must also differ in lightness).
